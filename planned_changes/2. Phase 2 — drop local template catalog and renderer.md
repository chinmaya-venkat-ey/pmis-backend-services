# 2. Doc 38 phase 2 — drop local template catalog and renderer

## Why

Doc 38 phase 1 (planned_changes/1) moved the `/api/v3/master/notification_templates/*` admin surface to PMIS-notification-service, while leaving user-mgmt's local handlers + model + bootstrap seed in place as a transitional fallback. That left two unwanted properties:

- The user-mgmt OpenAPI spec still advertised `/api/v3/master/notification_templates`. Anyone reading the user-mgmt Swagger thought they had two sources of truth — they didn't.
- `HttpNotificationClient.send` still rendered locally (looked up the template from user-mgmt's DB, computed placeholders, formatted) and only used notification-service for the actual provider call. That meant the catalog was *physically* duplicated — a row in user-mgmt's `notification_templates` and a row in notification-service's. Update one, drift from the other.

Phase 2 collapses both: drop the local handlers, drop the local model + seed, and route every dispatch through notification-service's new `/api/v1/notifications/dispatch` endpoint.

## Wire shape (after)

```text
caller
  → user-mgmt.HttpNotificationClient.send(channel, recipient, template_kind, payload, user_id)
    1. INSERT notification_log (status=queued)
    2. POST {NOTIFICATION_SERVICE_URL}/api/v1/notifications/dispatch  body={channel, recipient, template_kind, payload, user_id}
    3. parse response: success/provider/message_id
    4. UPDATE notification_log SET status='sent', payload=payload || {_dispatch:{provider, message_id, service_message}}
```

If notification-service is unreachable, the audit row stays as `failed` with a typed error message — same behaviour as before, just a single dispatch URL to fail at.

## What stays the same

- `MockNotificationClient` is unchanged. Tests that don't want HTTP keep using it (default in dev).
- The factory `get_notification_client(db)` selection rules are unchanged.
- Constants `CHANNEL_EMAIL`, `CHANNEL_SMS`, `TEMPLATE_OTP_LOGIN`, `TEMPLATE_PASSWORD_RESET_LINK`, `TEMPLATE_PASSWORD_RESET_OTP` still live here — they're identifiers callers pass to `client.send(template_kind=...)`.
- The `notification_log` audit table is unchanged. user-mgmt still owns "did the system attempt to notify?" as its local audit story; notification-service owns "did the provider succeed?".

## What this means going forward

See [points_to_consider/doc-38-no-local-template-rendering.md](../points_to_consider/doc-38-no-local-template-rendering.md). Short version: never re-introduce a `notification_templates` table or a renderer here. Add new template kinds in PMIS-notification-service.
