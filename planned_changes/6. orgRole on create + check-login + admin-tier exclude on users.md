# Doc 6 — orgRole on create, check-login, admin-tier exclude on /users

> **Status: SHIPPED** — landed on `dev` in both this repo and the
> monolith mirror.

Three small but FE-visible changes that landed together as a single
batch after the doc-5 hierarchy hardening:

| # | Sub-change |
|---|------------|
| 1 | `POST /users/create` now requires `orgRole` in the body and persists it to a new `users.org_role` column (so a user's primary tier survives a server restart and round-trips on GET). |
| 2 | New `GET /users/check-login?login=...` to let the Create User wizard validate uniqueness before the user clicks Save. |
| 3 | `GET /users` and the project-scoped user lists now exclude super_admin / admin holders so those tiers don't show up in pickers meant for project-level role assignment. |

---

## Why this exists

Pre-doc-6, the FE could only learn the org-tier of a user by querying
their `user_role_assignments` rows and inferring it — a multi-call
round-trip. Storing `org_role` as a column makes the projection
trivial. The check-login endpoint replaces the previous "try-create
and parse 409" pattern that broke the wizard's UX. The picker
exclusion plugs a real FE bug where admins were assignable to
project-tier roles and downstream RBAC then ignored the assignment.

## What's in scope / out of scope

- ✅ `users.org_role` column + alembic migration (idempotent
  backfill from `user_role_assignments` for legacy rows)
- ✅ `orgRole` mandatory on POST `/users/create`; PATCH accepts it
  and re-syncs the column
- ✅ `GET /users/check-login` (admin only; 200 with `{available: bool}`)
- ✅ Listing endpoints filter out `admin` / `super_admin` from
  project-scoped pickers
- ❌ Persisting historical `org_role` audit trail — only the current
  value is stored; per-change history is in `user_role_assignments`

## API surface

| Method | Path | Permission | Notes |
|--------|------|-----------|-------|
| POST | `/api/v3/users/create` | `users:create` | `orgRole` now required in body |

Affected listing endpoints (semantics change — admin tiers now hidden):
- `GET /api/v3/users` (when scoped to project pickers)
- `GET /api/v3/users/{id}/projects`

### Lessons learned

- Adding a column that *mirrors* derivable state (here, `org_role`
  derivable from `user_role_assignments`) is a net win for FE
  ergonomics IF the column is the single source of write — every
  write path must update both the assignments row AND the column.
  Lock-step is enforced in the service layer; tests assert it.
- `GET /users/check-login` is a deliberate exposure of a uniqueness
  predicate. Rate-limit if it ever moves outside an authenticated
  admin surface; for now the admin guard is sufficient.
